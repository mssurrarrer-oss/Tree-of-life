# Care Alert Integration Guide

## Goal
Connect live camera and wearable events into AI Hub trigger policies with minimal operational risk while keeping the workflow conservative and caregiver-friendly.

## Event Schema Requirements
Each incoming event should include:
- eventId
- eventType
- timestamp (ISO 8601)
- source
- role/context fields required by trigger rules (personRole, zone, confidence, heartRate, spo2, missedMinutes, etc.)

## Recommended First-Release Events
- person_detected
- door_activity
- inactivity_alert
- fall_detected
- checkin_missed
- wearable_vitals
- device_status

## Integration Steps
1. Connect camera and wearable outputs into Home Assistant or Node-RED.
2. Normalize events into JSON objects that match care-alert-triggers.json conditions.
3. Save samples in services/automation-framework/care-alert-sample-events.json.
4. Validate with tools/run-care-alert-simulation.ps1.
5. Route high severity actions to at least two contacts.
6. Keep a local audit log in knowledge/checkins/ for each alert.

## Safety Controls
1. Require explicit caregiver confirmation for non-urgent automations.
2. Keep high-severity alerts immediate and redundant.
3. Maintain audit logs in knowledge/checkins/.
4. Review thresholds weekly for false positives and false negatives.
5. Treat vitals alerts as support signals, not a medical diagnosis.

## Go-Live Checklist
- Trigger simulation run passes expected matches.
- Two-contact escalation tested.
- UPS and network redundancy validated.
- Privacy and consent boundaries documented.
- At least one watch-based fall alert and one camera-based inactivity alert have been exercised.

## Suggested First-Release Workflow
- Watch reports fall -> immediate caregiver alert and voice prompt.
- Camera detects prolonged inactivity -> caregiver prompt with timeline entry.
- Door activity at night -> safety timeline notification.
- Low SpO2 or abnormal heart rate -> support alert for caregiver review.
